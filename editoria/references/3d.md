# 3D como material (integración opcional)

EditorIA renderiza **motion graphics 2D**: 39 tipos de escena, física de
muelles, tipografía y color. Eso no cambia. Lo que hay fuera es **material en
3D** para las piezas que lo necesitan: un objeto, un producto, una maqueta, un
escenario.

**El límite, y es el que hace que esto no sea un motor nuevo:** el 3D no se
renderiza dentro de EditorIA. Se **pre-renderiza** y entra como un **overlay
con alfa**, exactamente igual que una capa que llega del editor. El motor, la
puerta, la mezcla de sonido y la auditoría no cambian: cambia de dónde sale
la imagen.

## Cuándo ofrecerlo

- El objeto que hay que mostrar **no existe en 2D** (un producto, un
  vehículo, una máquina) y dibujarlo con el motor sería una caricatura.
- La pieza necesita **girar** un objeto o **revelarlo** girando.
- Hay una **referencia visual** (una foto, un render, un dibujo) y el objeto
  tiene que reconstruirse **en código**, para poder animarlo.

Y su reverso, que es lo importante: **si el 2D del skill resuelve el plano,
no se ofrece 3D.** Un objeto que cabe en una escena de `escenas.md` no
necesita un render 3D: sale más rápido, es editable y pasa la puerta sin
dependencias.

## Las dos fuentes

### 1. Blender por MCP — modelar y montar en 3D

`ahujasid/blender-mcp` (MIT; el paquete en PyPy ahora se llama
`mcp-for-blender`, y `uvx blender-mcp` sigue funcionando sin cambios de
configuración) conecta Blender con cualquier agente: el agente **dirige**
Blender (malla, material, cámara, luz) en vez de escribir un archivo a mano.

```bash
# el servidor (una vez); el cliente MCP lo declara el usuario
curl -LsSf https://www.mcp-for-blender.com/install.sh | sh
```

Da control de la escena, no solo el render: es la vía para **encuadrar** (la
cámara), que es donde se juega la mayor parte del valor en una pieza.

**Aviso**: Blender no viene instalado. Se declara como dependencia opcional
(como Remotion o HyperFrames) y **no se instala solo**: se le pregunta al
usuario, igual que con el resto del software del sistema.

### 2. img2threejs — del objeto de referencia al modelo en código

`img2threejs/img2threejs` (Apache-2.0) reconstruye el objeto de una imagen de
referencia como **modelo procedural de Three.js, solo código**: no es
fotogrametría, no descarga assets, no extrae mallas. El modelo se genera por
etapas ("sculpting") con autocomprobación por visión.

```bash
node <repo>/bin/img2threejs.mjs --help    # el binario es Node puro
```

- **A favor**: el modelo es **código**, así que se anima con parámetros (no
  con keyframes grabados) y entra en la cadena de render del proyecto.
- **En contra**: necesita Node y una imagen buena; la salida es un `.js` de
  Three.js, no un archivo de render.

## Cómo entra en la pieza

El camino es el del **modo híbrido**, y por eso no hay trabajo nuevo:

1. El render 3D sale como una capa **con alfa** (ProRes 4444 / WebM, lo que
   diga `references/modos-produccion.md`).
2. Esa capa se mete en el `plan.json` como una escena de overlay, con su
   `at` y su duración, y **el motor hace lo de siempre**: la compone, la
   audita y la mide.
3. La puerta (`scripts/qa_entrega.py`) no cambia: sigue mirando la pieza
   entera.

La ventaja de este camino es que **el alfa sale del render, no de un
rectángulo**: la matte del objeto es real, y el desenfoque sale de ella
(`alphaextract` + `boxblur` + `lut`, el mismo camino que ya usa el modo
híbrido). Un recorte geométrico —círculo, polígono, radial-gradient— que
imite el contorno de un objeto es la versión barata del efecto, y se lee
peor que no ponerlo.

## Lo que NO se hace aquí

- **No se reescribe el motor** para que renderice 3D. El 3D es material.
- **No se copia código de estos repos**: se declara la fuente, se usa su
  herramienta y se escriben aquí solo las reglas que son de esta skill.
- **No se instala nada por el camino de atrás**: si el usuario no tiene
  Blender, se le dice y se sigue con 2D.

## La frontera

Si una pieza necesita 3D, casi siempre necesita también **encuadre, luz,
reflejo y sombra con offset** — y eso ya está en `references/principios.md` y
`references/animacion.md`. El 3D no cambia el listón: cambia el material de
las capas.
