# Internationalization (i18n) — how EditorIA handles language

## The rule

- **Documentation, code, comments, identifiers**: written in **English**. This
  is the language of the codebase, of GitHub, of the technical ecosystem.
  The validator, the references, the script docstrings, the in-code
  comments — all in English. New contributions should be in English.

- **Agent response to the user**: in the **language the user writes in**.
  When the user writes in Spanish, the agent replies in Spanish; when in
  English, in English; the same for any other language. This is documented
  at the top of `SKILL.md` (the "Language rule (read first)" block).

- **Skill content** (transcripts, captions, voice-overs, plans, brand copy):
  in **whatever language the source provides**. The skill does not assume
  any source language. Whisper transcribes any language; ElevenLabs TTS
  supports multiple voices per language (`references/sonido.md` lists them).

## How the agent should respond

1. The first user message in a session sets the response language for the
   whole session. Detect the language, not the platform locale.
2. If the user switches language mid-session, follow them. Do not ask
   "should I respond in English?" — just switch.
3. **Code, identifiers, file paths, log lines, error messages**: always
   in English (technical reality). Only the prose around them follows the
   user's language.
4. If the user's brief mixes languages (e.g. "Make me a video, con un
   tono muy serio"), use the dominant language in the brief as the
   response language. The brief content is kept verbatim regardless.
5. Brand voice (e.g. DragonJAR pack) is independent of response language.
   The agent responds to the user in the user's language; the brand
   voice inside the video can be a third language if the user requests it.

## How content works in any language

- **TTS** (`scripts/voz_off.py`): per-scene `voz` field in the plan. The
  voice roster (`VOCES` in the script) has multiple languages. The
  default voice is the language the user is writing in (auto-detected).
- **Music** (`scripts/musica.py`): the prompt is multilingual. The model
  is language-agnostic.
- **Transcription** (`scripts/alinear.py`, `scripts/voz_off.py`): Whisper
  auto-detects the source language; pass `--idioma` to force.
- **Captions** (`scripts/ffmpeg_tools/caption.py`): same; subtitle text
  is whatever you put in the SRT.
- **Brand copy / share copy** (`references/share-copy.md`): the share
  copy templates have one entry per language; the user picks.

## Validation of this rule

The validator does not currently auto-check the response language (that
is an agent behavior, not a file property). It DOES enforce:

- The `description` in `SKILL.md` frontmatter contains the "when" condition.
- No angle brackets (`<` `>`) in markdown that look like HTML/XML tags.
- All referenced files exist; all scripts compile; all scenes render.

## Adding a new language

If a user wants a language that is not in the voice roster or
brand pack, the agent can:
1. Add the voice to `VOCES` in `scripts/voz_off.py` (an ElevenLabs voice_id).
2. Add a brand pack entry under `brand/`.
3. Add a row to the TTS roster in `references/sonido.md`.

No code changes to the rendering or animation pipeline are needed:
PIL/ffmpeg are language-agnostic.
